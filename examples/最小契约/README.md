# 最小契约：报销单

> 第一次看这个仓库，从这里开始。三条判据、三张单子、七十一行契约 —— 别的都不用先读。
> 它不证明框架完整，只证明一件事：**一段原话能变成一个会红的判据，而红指得到具体那一条记录。**

## 1. 跑

```bash
python tools/score.py "examples/最小契约/报销单契约.json"
```

真的输出（不是"应该"）：

```text
E1   报销金额必须等于发票合计　1/1　做到
   ✅ 阻断·E1-a    amount 等于 invoice_total
              3 条记录 · 1 个子句全部成立
按需求：E1 100%　E2 100%　E3 100%
总分 100 / 100
结论：通过
```

## 2. 让它红

把 `报销单.json` 里 `B-001` 的 `amount` 从 `128.00` 改成 `128.10`，再跑一遍：

```text
E1   报销金额必须等于发票合计　0/1　未做
   ❌ 阻断·E1-a    amount 等于 invoice_total
              1 处不合格：B-001 amount=128.1 与 invoice_total=128.0 不一致，这里必须相等
总分 67 / 100
结论：不通过（阻断项 E1-a 未过）          ← 退出码 1
```

看两处：**证据指名到 `B-001`**，**结论指名到 `E1-a`**。只说"不通过"的报告，等于什么都没说。
这条红、这条绿的判法，`tests/test_examples.py` 里钉着 —— 教程里的数字也不会自己漂。

## 3. 三步，少一步都不算

| 段 | 这一份里写的 | 反例（写不出就说明还没想清） |
|---|---|---|
| **原话** | 「金额跟发票对不上，就别往上报。」 | 「金额要准确」 |
| **最小闭环** | 打开单子 → 读 `amount` 与 `invoice_total` → 不等就停下 | 「支持校验金额」 |
| **判据** | `compare: amount = invoice_total`，阻断 | 「应该能发现问题」 |

中间那一步是分水岭：**写得出一口气走完的三个动作，才写得出判据。**

## 4. 换成你的活

1. 复制 `报销单契约.json`，改 `id` / `name` / `profession`；
2. `E1` 里把 `amount` / `invoice_total` 换成你的两个字段，`path` 换成你的数据文件；
3. 四条子句先用满 —— `required` / `forbidden` / `compare` / `sla`。用不动了再想新子句，
   而不是反过来。

写不出 `why` 的判据就删掉：它守不住任何红线，只会消耗维护成本。

## 5. 它不是什么

- 不是职业模板 —— 那三份在 `contracts/`（教培、工单质检、以及治理自己的两份）；
- 不是样板间 —— 会计那个不在本仓库（原因见 [`docs/样板间-会计.md`](../../docs/样板间-会计.md)）；
- 不是脚手架 —— 没有生成器，复制粘贴就够了。**一个要装包才能用的示例，第一步就会劝退人。**
