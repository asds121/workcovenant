# 样板间 · 工程验收

第四个职业模板，也是第三次「换职业」。同一个引擎、同一份 schema，
只把判据内容从「工单」换成「整改单」—— 字段全换，机制一个字没动。

```bash
python tools/contract_check.py contracts/工程验收.json   # 先体检
python tools/score.py contracts/工程验收.json             # 再打分
```

## 两个数据文件，各管一件事

| 文件 | 是什么 | 谁在用 |
|---|---|---|
| `整改单.json` | 10 条全合规的整改单 | 契约的默认路径，跑出来必须是 100 分 |
| `整改单-坏.json` | 7 条故意写坏的，**一条只犯一个错** | `tests/benchmark_data.py` 喂给判据，证明七条判据各自会红 |

## 七条判据在守什么

| 判据 | 守的红线 | 坏样本 |
|---|---|---|
| F1-a | 「已整改」是施工方的一句话，不是证据 | `X-002` 关了，但没人复验 |
| F2-a | 自己改自己验，只会把错误复核成一致 | `X-003` 整改人与复验人都是 `team-A` |
| F3-a | 照片是现场唯一能搬运的证据 | `X-005` 只有整改前 |
| F3-b | 同一张照片当"前""后"，等于没有现场记录 | `X-004` 前后同一个文件 |
| F4-a | 验收是一个时刻：那一刻高危还开着，就不该签字 | `X-001` 高危没有 `closed_at` |
| F5-a | 照片证明「做了」，报告证明「合格」 | `X-006` 要报告，却没有报告编号 |
| F6-a | 例外必须比正常路径留痕更多 | `X-007` 有理由、有时间，没人批 |

`F4-a` 值得单独说一句：**缺 `closed_at` 判红，不判灰。** 缺料在别的判据里是「没验」（退出码 2），
但验收的场景里，高危没有关闭时间不是"料还没到"，是"它现在还开着" —— 这时候灰就等于放行。

## 数据

全部虚构。工地写成 `3F-东区` 这类位置编号，整改方 `team-A`，复验人 `inspector-0N`，
照片路径指向不存在的文件（判据只比对路径字符串，不读图片）。
