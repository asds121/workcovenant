## 0. 这份文档管什么

- 它**不管**功能全不全（那是 `PRD.md`），只管**必须做到、并且能被机器判到**的事。
- 每条必须写三段：**原话 / 最小闭环 / 判据**。少一段，这条就不算数。
- 判据编号（如 `R4-c`）与 `tools/req_score.py` 的 checker id **一字不差**。
  文档说"有"、脚本测不到 —— 那就是又一次甩锅。
- 判据分三层，**都算数**：

| 层 | 在哪 | 回答什么 |
|---|---|---|
| 打分 | `tools/req_score.py`（29 条，起窗口按真键量像素） | **现在**做到没有 |
| 钉子 | `tests/test_requirements.py`（27 项 pytest） | **以后**会不会退化 |
| 反证 | `tools/mutation_check.py --run`（17 条） | 钉子自己**咬不咬得住** |

  这三层之上还有一条**元判据**：`tools/definition_check.py`（验收里的 A21）盯着
  「`docs/项目定义.md` 说的东西还在不在」—— 引用解析得到、四个角色各有一条真实判据、缺口表不空。
  它自己也被反证咬过 2 条（编一个不存在的函数 / 把某个角色的判据列清空）。

  只有打分 → 下次改坏了没人拦；只有测试 → 又退回"测了什么就算做了"。
  钉子层里有一条专门盯着**别的钉子还在不在**：`test_判据编号一个都不许丢`
  把 29 个编号写死，少注册一条就红 —— 判据靠 import 的副作用注册，
  少 import 一个文件，剩下的照样 100 分（2026-10-20 真实发生过一次）。

- 状态只有四种：**做到 / 部分 / 未做 / 未验**。「未验」不算过。
- 打分：每条需求的得分 = 通过判据 ÷ 全部判据；**一条都没过 = 未做**。
  总分 = 11 条（8 条 + 3 个「适」）的平均。脚本退出码：0 全做到 / 1 有未做 / 2 有判据没验完。

## 1. 「最小闭环」是什么意思

一条需求 = **一段能一口气走完的动作**，走完就知道有没有。例：

> 右键纸上一处 → 那里冒出编辑框 → 打两个字选一笔 → Enter → 表述贴回**那个点**上

五步，任何一步断掉这条就是"未做"。没有"基本支持""兼容处理"——那些词就是甩锅的入口。

## 2. 八条硬要求

### R1 抬头：几月、到月末没有；默认自动，人一指定就固定

**原话**
> 「进来之后上方显示月份和是否到了月末，这个一般自动变，如果人指定了之后，他就只能是按这个来，
> 　除非人主动改为自动。」

**最小闭环**：不动任何设置 → 把系统日期推到下个月 → 抬头自己变了；
点一下「固定」→ 再推下个月 → 抬头不动；点「改回自动」→ 立刻回到当月。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| R1-a | 不指定时按"今天"算：喂 2026-11-02 → 期号 `11月`，阶段 `月中` | 机检 |
| R1-b | 指定 9月 后喂 2026-11-02 → 期号仍是 `9月`（不许自己变） | 机检 |
| R1-c | 改回自动后立刻按"今天"算；抬头那句话本身能看出当前是**自动**还是**已固定** | 机检 |

**现状**：见 §4（脚本产出）。

### R4 右键定位：在**那个点**上唤起编辑框，收付必居其一

**原话**
> 「右键单击一个地方，唤起编辑框，这时可以按两键确定一个业务，也可以手动输入。
> 　这个右键单击的地方作为坐标来标记单据位置。要求：无论是按两键确定一个业务还是手动输入，
> 　都必须显示包含收付信息，且只能要么收，要么付。对于结转分录等不需要收付的，
> 　必须点界面上面的"无流水分录"按钮来增加。」

**最小闭环**：右键纸上某处 → 菜单第一项「在这里记一笔」→ 打「付」→ 选「货款」→ Enter
→ 这笔的坐标就是刚才那个点；不写收/付 → **长不出业务**（必须点上方「无流水分录」）。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| R4-a | 右键之后工具知道"在哪个点"（归一化坐标，不是只有屏幕坐标） | 机检 |
| R4-b | 坐标进数据：这笔业务记得住 `page + (x, y)`，重开还在 | 机检 |
| R4-c | 收付唯一：有且只有一个方向才放行；「结转成本」这种没有方向的不许直接成业务 | 机检 |
| R4-d | 上方有「无流水分录」按钮；点了能建"无收付"的业务，且它不被 R4-c 拦 | 机检 |

### R7 分录：按需预览 + 四态 + 只有提交才外流、才回灌

**原话**
> 「主动点击显示分录预览，才显示分录。这个分录分为待挑选状态、保存状态、提交状态、审核状态。
> 　保存状态仅要求完整，提交状态需通过进行交叉核验。如果一个业务表述它有提交状态的分录，
> 　那么它会通过共享发送给实习生模块，用于提升他们的识别质量。提交状态的时候，
> 　你可以选择接收实习生模块返回的信息，来补充分录至完整分录。」

**最小闭环**：打开详情 → **没有分录表**（要点「分录预览」才有）→ 挑腿 → 保存（只要求完整）
→ 提交（跑交叉核验，过了才动）→ 提交后共享层多一条带指纹的记录 → 选「收实习生补全」→ 空字段被填上。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| R7-a | 打开窗口时**不显示**分录预览；点了才显示 | 机检 |
| R7-b | 四态都在状态机里：`draft / saved / submitted / approved`，非法迁移被拒 | 机检 |
| R7-c | 只有提交写共享层（保存不写），且带快照指纹 | 机检 |
| R7-d | 提交态能接收实习生返回的补全，且**只补空、不覆盖** | 机检 |

### R8 审核即签名：之后不能动；要动必须带理由

**原话**
> 「如果这个分录找不到任何问题，可以进行审核，审核之后，这个分录就不能再动了。
> 　如果要动，必须显示附理由。」

**最小闭环**：审核 → 再想改分录 → 被拒且说得清为什么；反审核不写理由 → 被拒；写了理由 → 放行并留痕。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| R8-a | 审核后冻结：改分录的入口全部拒绝（不是"提示一下还能改"） | 机检 |
| R8-b | 反审核必须带理由：空理由拒；留痕里能查到理由、时间、从→到 | 机检 |

## 3. 三个「适」

### S1 不动的情况下，重要的东西全在视野内

**原话**
> 「要求在投不动的情况下，重要的东西全部在视野内」

**最小闭环**：默认窗口打开 → 抬头、纸、业务表述条、底栏四块都在窗口矩形里，
不需要滚动、不需要最大化、不需要拖。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| S1-a | 默认尺寸下四块的几何矩形都落在窗口内（且底栏没被顶出屏幕） | 机检 |

---

### S2 每个业务表述至少 4 平方厘米

**原话**
> 「每个业务表述至少占用4平方厘米的空间」

**最小闭环**：量一条表述的实宽实高，按**物理 DPI** 换成厘米，面积 ≥ 4 cm²。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| S2-a | 单条表述面积 ≥ 4.0 cm²（`px / physicalDPI × 2.54`，不许按 96 假装） | 机检 |

---

### S3 输入业务表述 = 输入法

**原话**
> 「输入业务表述要像输入法一样的体验，即时出字，显示在编辑框附近，体验完全和输入法一样。」

**最小闭环**：敲第一个字 → 候选立刻出现 → 候选偏偏贴在**编辑框/输入点**旁边（不是窗口另一头）。

**判据**

| 编号 | 怎么验 | 类型 |
|---|---|---|
| S3-a | 第一个字就出候选（不用回车、不用点） | 机检 |
| S3-b | 候选浮层与输入点的距离 ≤ 120px | 机检 |

### 4.2 这份分数的可信度

- 每条判据都会**起窗口、按真键、量像素**；缺料时记「—」，**不算过**。
- 判分脚本自己有过两个假绿灯，都当场改成真判据（写在判据的注释里）：
  ① 用 `isVisible()` 量分录表 —— 窗口没 show 时永远 False，白过；
  ② 用 `geometry().topLeft()` 去 `mapTo` —— 父坐标当本坐标，量出底栏在 y=1454（窗口才 760）。
  **判据错的时候，红灯绿灯都没有意义。**
- 所以钉进 pytest 的那几条，都**先做坏一次**证明它会红（`tools/mutation_check.py --run`，
  2026-10-20 实测 6/6 变红）：R7-a 一打开就露着分录 / R8-a 审核过了还能改 /
  R8-b 空理由也放行 / R7-b「待挑选」不见了 / R4-c「收付款」被硬判成一边 / R4-b 落点没存盘。
  改完立刻还原，并用 sha1 校验原文一字未变。

### 4.3 100 分**不算数**的地方（先写下来，免得下次当真）

1. **提交的三路核验**：只验"提交路径里调了交叉核验"，没验"冲突真的把提交拦住了"
   （那是验收清单 A 系列的事，不在 R7 这四条里）。
2. **整月批量**：单张走通了，68 张一起提交/审核的逐笔回执没验。
3. **4cm² 只在离屏 100dpi 上量过**：他真机 175% 缩放下的实际厘米数要再量一次。
4. **中文输入法**：拼音候选是程序内实现的，走真实 IME（微软拼音）那条路没验。
5. **"三路"里的发票/回单**：本期 10 月没有银行流水，回单那条路是空的 ——
   判据在缺件时会自动降级，降级到底算不算过，得等料齐了再看。
