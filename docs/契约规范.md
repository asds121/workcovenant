# 契约规范 v1.0（冻结）

> **状态**：已冻结。`format` 字段的值 `workcovenant.contract/1` 就是这一版的身份。
> 任何**不兼容**的改动必须升到 `/2` 并附迁移规则 —— 半改不升，就会长出方言，
> 而方言是这类框架最常见的死法（核心文档 §10.1）。
>
> 2026-10-23 加第五种判据 `data`（§3.2）与字段白名单（§3.3 第 4 条）：
> 前者是**新增**，后者是**收紧**，都不改 format —— 老契约只要没写错字段就照跑（§7）。

这一版只回答三件事：**契约怎么写、判据怎么跑、分数怎么算**。
它不知道"凭证""错题""工单"是什么 —— 那些是各职业契约里的判据内容。

---

## 1. 文件

- UTF-8 编码的 JSON，一个 `.json` 文件 = 一份契约。
- 机器可读部分（本规范）与叙述部分（`note`、`verbatim`）同文件，**不拆两份**：
  拆开之后叙述一定先烂，而且没人会发现。

### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | ✅ | 固定 `workcovenant.contract/1` |
| `id` | string | ✅ | 契约标识，kebab-case，仓库内唯一 |
| `name` | string | ✅ | 人读的名字，如「教培能力契约」 |
| `profession` | string | ✅ | 这份契约属于哪个职业/场景 |
| `version` | string | ✅ | `x.y.z`，契约内容改了就要动它 |
| `owner` | string | ✅ | 谁负责这份契约（出事找谁，不是"团队"） |
| `note` | string | | 一两句说明：这份契约的边界、样例数据在哪 |
| `requirements` | array | ✅ | 非空，元素见 §2 |

---

## 2. requirement（一条强要求）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 如 `R1`、`L2`；全局唯一 |
| `title` | string | ✅ | 一句话说清这条要求 |
| `verbatim` | string | ✅ | **原话**：谁在什么场景说的。没有原话的要求是二手转述，会走样 |
| `loop` | string[] | ✅ | **最小闭环**：一段能一口气走完的动作，至少 1 步 |
| `criteria` | array | ✅ | 非空，元素见 §3 |

三段缺一不可。`loop` 为空的要求**不算数**：没有闭环就没有验收，
只剩一句"要支持 XX"，那正是甩锅的入口。

---

## 3. criterion（一条判据）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 如 `R1-a`；**全局**唯一 |
| `title` | string | ✅ | 怎么验，一句话 |
| `why` | string | ✅ | **守的是哪根红线**。写不出 why = 为了测而测 |
| `kind` | string | ✅ | `cmd` / `file` / `links` / `manual` / `data` |
| `blocking` | bool | | 默认 `false`。`true` = 一票否决 |
| `weight` | int | | `1/2/3`，默认 1。**只用于展示排序，不参与总分**（见 §5 的理由） |
| `requires` | string[] | | 前置料。缺了就记 `—`（**没验**），不算过 |
| `path` | string | `file`/`links`/`data` 必填 | 相对仓库根；**不许绝对路径、不许含 `..`** |
| `contains` | regex | `file` 可选 | 在文件内容里找，`re.MULTILINE`；匹配前 CRLF 已归一为 LF |
| `min_bytes` | int | `file` 可选 | 太小 = 空壳 |
| `run` | string | `cmd` 必填 | 命令；`{python}` 会替换成当前解释器绝对路径 |
| `expect` | object | `cmd` 可选 | `exit`（默认 0）/ `stdout_contains` / `stdout_regex` / `stderr_contains` |
| `timeout` | int | `cmd` 可选 | 1–600 秒，默认 120。超时记 `❌`（卡住的命令必须自己结束） |
| `evidence` | string | `manual` 必填 | 人工证据文件路径；同样不许绝对路径或 `..` |
| `assert` | array | `data` 必填 | 一批记录上的子句，见 §3.2 |

### 3.1 五种 kind

| kind | 判什么 | 怎么给证据 |
|---|---|---|
| `cmd` | 跑一条命令 | 退出码 + 输出片段原样带进报告；输出先按 UTF-8、再按 GB18030 解码 |
| `file` | 文件在不在、够不够大、内容对不对 | 文件大小 + 命中的那一行 |
| `links` | markdown 里的相对链接解析得到吗 | `N 条链接全部解析得到` 或断链清单 |
| `manual` | 机器判不了的事（观感、语义、现场） | 证据文件里写 `✅` / `❌`，没写就记 `—` |
| `data` | 一批 JSON 记录合不合规 | `N 处不合格：<记录 id> <差在哪>`；全部成立时报 `N 条记录 · M 个子句` |

`links` 认这四种写法：行内 `[a](b.md)`、带标题 `[a](b.md "t")`、尖括号 `<my file.md>`、
引用式 `[a]: b.md`；`%20` 会还原成空格。代码块与行内代码里的示例链接**跳过** ——
否则文档里教一次写法，检查就红一次。`http(s)` / `mailto:` / `tel:` / 纯锚点 `#x` 不算本地链接。

### 3.2 `data`：一批记录上的四个子句

数据文件是一个 JSON 数组，或 `{"items": [...]}` 的对象。每条记录是一个对象，
`id` 字段用来在证据里指名（没有就报"第 N 条"）。

一个子句 = 可选的 `when` + **恰好一个**判定子句：

| 子句 | 判什么 | 例子 |
|---|---|---|
| `required` | 这些字段都不许空（`0` / `false` 算有值） | `{"required": ["order_id"]}` |
| `forbidden` | 这些字段里不许出现这些词 | `{"forbidden": {"fields": ["text"], "terms": ["保证退款"]}}` |
| `compare` | 两条字段必须相等 / 必须不同 | `{"compare": {"pairs": [["a", "b"]], "expect": "ne"}}` |
| `sla` | 两个时间点相隔不超过 N 小时 | `{"sla": {"start": "opened_at", "end": "responded_at", "max_hours": 24}}` |

`when` 是过滤条件，只影响**这条记录要不要判**，不影响判定本身：

```json
{"when": {"field": "risk", "in": ["high"]}, "required": ["escalation_path"]}
{"when": {"field": "contact_human", "nonempty": true},
 "compare": {"pairs": [["contact", "contact_human"]], "expect": "eq"}}
```

四条硬口径：

1. **`when` 不成立就不判** —— 条件没满足时不许无辜变红。
2. **时间缺失算红**，不算灰：证明不了未超时，就是没做到。
3. **`sla` 只用记录里的时间**，绝不用"现在" —— 不然同一份数据两次跑分不同，可重放就没了。
4. **一个子句只判一件事**。想要"高风险必须有升级路径、且必须有人复核"，
   就写两个子句（或两条判据），不要发明一个复合子句。

### 3.3 两条硬规则

1. **`blocking` 不许用于 `manual`。**
   一票否决权必须握在机器手里；靠人写 `✅` 的东西不能拦人。
   校验器会直接拒绝这种契约。
2. **`requires` 与 `path` 是两件事。**
   - `requires` 缺 → `—`（这条**不该判**，料没到）；
   - `path` 缺 → `❌`（这就是该交的东西，没交就是没做）。

   混成一个，就会得到"文件没交 → 显示未验 → 看起来没毛病"的分数。
3. **判据只许读仓库内的相对路径。**
   `path` / `evidence` / `requires` 里出现绝对路径或 `..`，契约**直接拒绝加载**。
   否则一份契约可以顺手把仓库外面的客户文件、密钥读进报告 —— 而报告是会贴进 issue 的。
4. **字段名不许写错，也不许放错判据类型。**
   不认识的键、或只属于别的 kind 的键（比如 `file` 判据上写 `run`），一律拒绝加载。

   这条听着像洁癖，其实是在堵一类最贵的假绿：`blockng: true` 会被静默忽略 ——
   判据照常加载、照常显示在报告里，**只是再也不阻断**。写错的键必须比没写更吵。

## 4. 三档结果

| 结果 | 记法 | 意思 |
|---|---|---|
| `pass` | ✅ | 过了，证据一句话可复核 |
| `fail` | ❌ | 没过，证据写清**差在哪**（差在哪 = 下一步做什么） |
| `skip` | — | **没验**（缺料 / 没留证据）。不算过，也不许当成过 |

判据执行过程中抛异常，一律记 `❌`（含异常类型与消息），绝不冒泡成"整个脚本挂了"。
**一个判据写坏了，不该让另外十条失去意义。**

## 5. 打分与退出码

```text
需求得分 = 通过判据数 / 判据总数        # skip 进分母、不进分子
总分     = 各需求得分的平均 × 100       # 需求等权
```

- **需求等权**：否则"判据多的那条"会绑架总分，写得多的人天然高分。
- **`weight` 不进总分**：权重一进公式，就会有人靠调权重而不是靠做事来抬分。
  它只用于报告里的展示排序。

### 阻断项

任何 `blocking` 判据为 `fail` → 结论 `不通过（阻断项 X 未过）`，退出码 1。
但**总分照常显示**：把分数抹成 0 会掩盖其它进展，把阻断藏进总分又会让它被平均数稀释。
两件事必须分开说。

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 全部判据通过 |
| `1` | 有判据没过（含阻断一票否决） |
| `2` | 没有未过，但有未验 —— **2 不是通过** |
| `3` | 契约本身坏了（schema 不合法），一分都不该信 |

`1` 优先于 `2`：一条红不能被一条灰盖掉。
`3` 单独留一个码：**"契约写错了"和"事情没做好"必须分得开** ——
前者怪写契约的人，后者怪干活的人，混在一起就又变成甩锅。

## 6. 校验（全量，不做"遇到第一个错就停"）

加载时下列任一不成立，就抛错并**一次列出全部问题**，消息里带需求/判据 id：

- `format` 不等于 `workcovenant.contract/1`
- 顶层必填字段缺失；`version` 不是 `x.y.z`
- `requirements` 不是非空数组
- requirement 缺 `title` / `verbatim` / `loop` / `criteria`
- requirement id 重复；criterion id 重复（**跨需求也算重复**）
- criterion 缺 `title` / `why`
- `kind` 不在五种之内
- 出现不认识的字段；字段只属于别的 kind（如 `file` 判据上写 `run`）
- `cmd` 缺 `run`；`expect` 里出现不认识的键（写错的键必须报错，不许当没看见）
- `file` / `links` / `data` 缺 `path`；`manual` 缺 `evidence`
- `data` 的 `assert` 为空、子句不是恰好一个、子句参数不合规
- `blocking` 用于 `manual`
- `weight` 不在 `1/2/3`；`min_bytes` 为负
- `timeout` 不在 `1..600`
- `path` / `evidence` / `requires` 里出现绝对路径或 `..`

## 7. 版本演进

| 改动 | 要不要升 `format` |
|---|---|
| 加可选字段（老契约照跑） | 不升，`version` 动小版本 |
| 加新 `kind` | 不升（引擎不认就该报错，而不是猜） |
| 改判据语义、改字段含义、改打分公式 | **升到 `/2` + 写迁移规则** |
| 删字段 | **升到 `/2`** |

升版时必须同时交：迁移脚本、老契约在新引擎上的跑分对照（同一份契约两版分数差在哪、为什么）。

## 8. 最小完整示例

```json
{
  "format": "workcovenant.contract/1",
  "id": "demo",
  "name": "最小契约",
  "profession": "示例",
  "version": "1.0.0",
  "owner": "你的名字",
  "requirements": [
    {
      "id": "R1",
      "title": "交付件在",
      "verbatim": "「别发我网盘链接，放仓库里。」—— 2026-10-20 用户原话",
      "loop": ["打开仓库", "看到文件", "点开能读"],
      "criteria": [
        {
          "id": "R1-a",
          "title": "README 存在且不是空壳",
          "why": "没有 README 的仓库等于没有交付",
          "kind": "file",
          "blocking": true,
          "path": "README.md",
          "min_bytes": 400
        }
      ]
    }
  ]
}
```

```bash
python tools/contract_check.py contracts/demo.json   # 先体检：契约写全了没有
python tools/score.py contracts/demo.json            # 再打分：做到没有
```

顺序不能反。**先跑分后体检，等于先看答案再看题。**
