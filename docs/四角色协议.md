# 四角色协议 v0.1

> 单人背后的一支数字团队。**每个角色的红线和它做的事一样重要 —— 红线才是这个产品。**

这份协议是框架层的一部分：它与行业无关，只规定**谁有权做什么、谁绝对不许做什么、
出了冲突谁优先**。会计、教培、工程验收只是同一套权力的三个实例（见 §5）。

---

## 1. 四个角色

| 角色 | 像什么 | 只有他能做 | **绝不许做** | 可判据的形态 |
|---|---|---|---|---|
| **你**（决策者） | 老板 | 定方向、确认结论、最终签字 | 不做重复劳动、不盯流程 | 待裁决占比、签字覆盖率 |
| **机器实习生** | 下属 | 抽取、补空、批量核对 | **不覆盖人工值**、不做审核 | 冲突必须记 `Conflict`，人工值零改写 |
| **数字流程经理** | 流程主管 | 拦错、锁定、留痕、评分 | **不做业务判断**、不替人决策 | 前置不齐时只返回"还差什么"，不返回候选 |
| **助理呈现层** | 好上司 / 教练 | 解释、提醒、引导、复盘 | **不命令**、不训导、不替人拍板 | 禁词表命中数为 0 |

一句能记住的分工：**实习生补空，经理拦错，助理解释，你签字。**

---

## 2. 四条红线，各自怎么判

红线如果不写成判据，它就只是口号；半年后所有实现都会从最省事的那条开始破。

### 2.1 不越权代签

- 机制：机器可以在"待裁决"状态下给建议，但**不能产生终态**。
- 判据形态：终态记录必须带责任人字段；责任人缺失 → 判红。
  比值类判据用"待裁决 ÷ 总条目"，`0` 表示账没有责任人，`> 阈值` 表示机器在替人干活。

### 2.2 不覆盖人工值

- 机制：实习生补空只写**空字段**；遇到"已有值 ≠ 实习生给的值"，记一条冲突，**一个字不动**，交给人。
- 判据形态：构造一条人工值 + 一条冲突的机器值，跑一遍补空，断言人工值字节级不变且冲突被记录。

### 2.3 不替人决策

- 机制：前置条件不齐时，流程经理返回的是**"还差什么"**，不是"最接近的候选"。
  给出候选就等于替人做了选择，人只会点第一个。
- 判据形态：造一条缺前置的记录，断言返回里**一个候选都没有**，且缺项清单非空。

### 2.4 不命令

- 机制：助理的话术里不许出现催办、警报、自贬、报进度四类词。
- 判据形态：维护一张禁词表，往任何一条助理文案里塞一个禁词，检测必须抓住。
  禁词表本身要被反证咬过（塞进去必须红），否则它只是装饰。

## 3. 冲突时谁优先

四角色会打架。默认优先级（从高到低）：

1. **你** —— 任何时候可以推翻机器，但必须留理由（推翻是权力，留痕是代价）。
2. **数字流程经理** —— 拦错优先于用户体验的顺滑。锁定就是锁定，不能"提示一下还能改"。
3. **机器实习生** —— 只在自己被授权的字段上说话，且不允许覆盖。
4. **助理呈现层** —— 只有解释权，没有决定权；它不能替任何一方说话。

判断实现有没有塌陷，只看一条：**助理能不能让流程放行。** 能，就是越权。

## 4. 闭环：人机互训，不是人机分工

```text
原始材料
  ├─ 人：原位判断 → 定方向 → 详情 → 签字
  └─ 机器实习生：抽取 → 字段 → Schema
        ↓
   交叉核验（人对机器）
        ↓
   提交的结论共享给机器实习生（人教机器）
        ↓
   机器实习生返回信息补空（机器帮人，**不覆盖人工值**）
        ↓
   审核锁定 + 留痕 + 评分
```

单人产品成立的关键，不是"团队协同"，而是**一个会成长的机器实习生 + 一个不徇私的流程经理**。
人没有同事复核，机器当第二双眼睛；人没有团队训练数据，提交的结论反哺抽取。

## 5. 迁移：同一套权力，三个职业

| | 会计（样板间） | 教培（已建契约） | 工程验收（待建） |
|---|---|---|---|
| 你 | 会计本人：定收付、确认分录、审核 | 学习者/家长：定目标、确认提交 | 项目经理：确认整改完成 |
| 机器实习生 | OCR 回单/发票、抽字段 | 批改、错题 Schema | 现场照片识别、问题清单 |
| 数字流程经理 | 收付互斥、三路核验、审核锁定 | 学习状态机、认证签名校验 | 整改状态机、复验门槛 |
| 助理 | 解释为什么被拦、下一步做什么 | 错因讲解、下一步练什么 | 整改建议、验收标准解释 |
| 证据链 | 凭证 + 回单 + 发票 | 练习记录 + 错因 + 认证签名 | 照片 + 检测报告 + 复验签字 |

判据内容全换，机制一个字没改 —— 这就是"框架"与"样板间"的分界线。

## 6. 塌陷清单（出现任意一条，这套模型就已经坏了）

- 助理开始催办、训人、报"我已完成 80%"。
- 流程经理在缺前置时给出"推荐值"。
- 机器实习生悄悄覆盖了人改过的字段。
- 审核之后还能改，或者改了不写理由。
- 评分开始评"这个人靠不靠谱"，而不是"这份工作合不合格"。
- 阻断项变成"提醒一下"。

**评分评工作质量，不评人的价值。** 这条越界，整套东西就从"好上司"变成"训导主任"。
